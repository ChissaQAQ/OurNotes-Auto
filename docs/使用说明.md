# 使用说明

[README](../README.md) 之外的详细说明：各任务的细节、游戏内设置、自动修正、拟人化、出意外时的处理、运行时文件和工作原理。命令行用法见[命令行](命令行.md)。

## 环境要求

- Windows，MuMu 模拟器 12（本项目在 MuMu 6.6.x、Android 15 实例上测试）
- 模拟器分辨率 **1280×720**（其他 16:9 分辨率会按比例换算，但未充分测试），帧率不低于 60（同步参数按 60 帧截图调整）
- 游戏：国际服（包名 `com.bilibili.sirius.official`），游戏语言为简体中文、繁體中文、English 或 한국어。导航靠 OCR 识别界面上的文字，其他服认不出按钮。한국어要把「游戏语言」选成 한국어：会多加载一个韩文文字识别模型（两个模型一起识别，每次识别慢一些）
- 游戏内设置见[游戏内设置](#游戏内设置)
- 能访问谱面站 `assets.bdon.moe` 与曲名接口 `haneoka.org`（检查更新另外访问 `github.com`，可以关掉）
- 发布包：两种界面都需要 [VC++ 2015–2022 运行库](https://aka.ms/vs/17/release/vc_redist.x64.exe)（MaaFramework 依赖）；MFAA 另外需要 .NET 10 桌面运行时（包里的 `DependencySetup_依赖库安装_win.bat` 可一键安装它和 VC++ 运行库），MXU 需要 WebView2（Windows 10/11 一般自带）。包里自带 Python 运行时、MaaFramework 与 OCR 模型，谱面在运行时从谱面站下载。各组件的许可证见 [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md)
- 从源码运行：Python ≥ 3.11，见[命令行](命令行.md)

## 连接模拟器

连接设置里选「MuMu 模拟器」，再选要用的模拟器实例。MuMu 12 第 n 个实例的 adb 地址是 `127.0.0.1:16384+32n`，例如第 0 个是 16384，第 1 个是 16416。截图和触控走 MuMu 的接口，安装目录由 adb 路径推出，所以目前只支持 MuMu 12。

## 任务

游戏停在主界面或自由演出选曲页即可；勾选「启动游戏」时，游戏没开也行。

| 任务 | 作用 |
|---|---|
| 启动游戏 | 游戏没在运行时启动它，点掉标题画面、登录奖励和公告，进入主界面。放在其他任务前面 |
| 切换账号 | 退出当前的 B 站账号，从游戏的登录记录里选填写的账号登录（不用输密码），然后进入主界面；已经在游戏里时先重启游戏回到标题画面。账号名填登录记录里显示的名字，写一部分也行，但要只对得上一个账号。只能切到登录记录里有的账号，新账号请先在游戏里手动登录一次。多个账号轮流打：任务列表里排成「切换账号（A）→ 其他任务 → 切换账号（B）→ 其他任务」。用户中心的「注销」、登录记录每行右边的 ⓧ 都不会点。演奏记录、记录汇总目前不分账号 |
| 重复刷歌 | 在自由演出里连续演奏，可选选曲方式（当前曲 / 随机 / 优先未 AP / 指定歌单）、难度、局数、每局消耗的 LB。难度选「优先高难度」时，「优先未 AP」从 EXPERT 到 EASY 依次补，都补完了按 EXPERT 随机；其他选曲方式按 EXPERT 打 |
| 清体力 | 连续演奏到 LIVE BOOST 用完（每局前看持有数，为 0 就结束），不用星钻。升级会回满 LB，所以局数可能比预计的多 |
| 挂机 | 和清体力一样打到 LB 用完，然后停在乐队确认页，按右上角的恢复倒计时等 LB 恢复到每局消耗数，再接着打（LB 每 30 分钟恢复 1 个，消耗 3 时约 90 分钟一局）。每局消耗选 0 时不等 LB：每局前看持有数，有 LB 就消耗 1 个，用完了改为消耗 0 接着打，恢复出来再消耗，一直打歌。一直运行到手动停止或打够局数；等待时遇到日期变更会重新登录，遇到服务器维护每 10 分钟看一次，开服后接着挂机。选项「定时收获」（默认开，间隔 4 小时）：开始时先领一次录音室练习，之后每隔设置的小时数（1~12）在两局之间或等 LB 时回主界面再领一次，领完回来接着挂机（录音室练习最多累计 12 小时，超过后效率降到 30%）；没领成的过 30 分钟再领。选项「每天领取日常」（默认开，22:30）：每天到设置的时间（电脑的本地时间）同样回主界面领一次任务、任务通行证、限定任务、新手任务、T.G.W CARD 和礼物盒，没领全的过 10 分钟再领一遍（一天最多 3 遍）。任务列表里的「领取日常」只在挂机前跑一次，挂机跨天后靠这个领；游戏每天 23:00 日期变更，领取时间要早于 23:00 才领得到当天的。不用星钻。它不会自己结束，请放在任务列表的最后 |
| AP补完 | 把所选难度（EXPERT / HARD / NORMAL / EASY）里还没 ALL PERFECT 的歌打到 AP。会临时把选曲页切到「全部」分类、筛选「未ALL PERFECT」，正常结束后改回原样 |
| 挑战演出 | 只在部分活动期间开放（没开放时报错结束）。从演出首页进「挑战演出」连续演奏，每局消耗挑战pt（CP）而不是 LB，打到 CP 不够一局为止。选项「每局消耗挑战pt」默认 200（×1，最省、能多打几轮），也可选 400 / 800 / 1600（奖励 ×2 / ×4 / ×8）或不改游戏里的设置；第一局前在「CP 设置」里选好并核对单选按钮后才点 OK。选曲方式「轮流打每首歌」（默认）每局换到列表里的下一首，到底了回到第一首；「优先打没 AP 的歌」每局开始前逐首看所选难度有没有 ALL PERFECT，先打没 AP 的（同一首最多打 3 次），都 AP 了再轮流打（难度选「优先高难度」时按 EXPERT → HARD → NORMAL → EASY 依次补）；也可以一直打当前选中的歌。乐队确认页的「跳过」不会点 |
| 领取日常 | 依次领取录音室练习（收获）、任务、通行证任务与 PASS 普通档（同时有几个通行证时逐个领）、限定任务、新手任务、T.G.W CARD、礼物盒的奖励，每项可单独关掉。只点亮着的「一键领取」和奖励弹窗的 OK；T.G.W CARD 领每日积分、每日奖励和商店专享商品目录里价格写着「免费」的商品，要星钻的不点；不认得的弹窗不点，报错停下。打完歌后每日任务才满，所以排在演奏任务后面。可选「看故事（跳过）」（默认关）：把没看过的乐队故事、视角故事、羁绊故事逐话跳过，解锁乐曲、领看完的奖励，每话第一次看要下载数据（无语音，乐队故事约 30MB） |
| 记录汇总 | 在日志里列出本工具的演奏记录，不操作模拟器 |

### LB 不足时用道具补充

重复刷歌、清体力、挂机、AP补完都有选项「LB 不足时用道具补充」（默认关）：每局开始前 LB 持有少于每局消耗数时，从「消耗LB」→「恢复」进去，只在「道具」页用 LIVE BOOST饮料补够这一局（先用小型 +1，不够再用 +10），核对选中的数量、恢复预览和确认弹窗上的数字都对得上才点 OK；不在「道具」页或有任何对不上就点取消、本次不再补充。绝不用星钻、不看广告。

子选项「最多补充」是本次运行最多补充的 LB 数，0 为直到饮料用完。饮料用完后按原来的方式继续（清体力就此结束，挂机开始等恢复）。需要把每局消耗 LB 设为 1~3。

### 其他选项

- 需要调整默认值以外的参数（如时间偏移）时，把 [config.example.yaml](../config.example.yaml) 复制为解压目录里的 `config.yaml` 再修改。界面里的选项优先于它。
- 界面日志默认只显示进度和结果。打开全局选项「调试日志」后，同步、谱面、触控等细节也会显示；完整日志总是写在 `data/ournotes.log`。
- 全局选项「检查更新」默认开启：每次任务结束时，如果 GitHub 上有新发布的版本，会在日志里提示下载地址。它不会自动下载，更新要手动下载新的压缩包。

## 游戏内设置

| 设置 | 建议 | 说明 |
|---|---|---|
| 节奏图示速度 | **5.00**（必须） | 同步参数 `play.sync.tau_s = 0.835` 是在 5.00 下测的。每局开始前会从演出前选项设置弹窗读出流速核对，不一致只在日志里警告、不会停下：其他流速仍能同步，但按键时机整体偏移。改回 5.00，或执行 `calibrate motion` 重新测量（另见[拟人化](#拟人化可选默认关闭)一节的流速要求） |
| MV / 背景 | 关闭，或换成较暗、不动的背景（必须） | 开局要等画面静止后再跟踪第一个音符。背景一直在动时最多等 4 秒就开始跟踪，亮的背景还会混进来，导致同步失败或不准 |
| 小节线显示（详情 → 节奏图示设置） | 开关都可以 | 开局跟踪第一个音符时，会认出横贯轨道的小节线并跳过。0.1.3 及更早的版本会把比第一个音符先落下的小节线当成第一个音符，整局提前、很快生命值归零，用这些版本时请关掉 |
| 特效、演出等级 | 不强制，电脑配置弱时建议调低 | 只在开局几秒看画面（这时还没有击打特效），彩色特效会被过滤；之后按谱面演奏，只看右上角的暂停按钮。但目前只在调低的设置下测过，高特效下可能有亮白色的开场特效混进跟踪区，或全屏演出连续遮住暂停按钮超过 2 秒被当成离开演奏画面而停止触控。调低还能让模拟器帧率更稳 |
| 乐队确认页「消耗LB」 | 用配置项 `game.lb_cost`（0~3）自动设置 | 第一局前自动打开弹窗选好并核对，游戏会记住。0 不消耗 LB（LIVE START 上显示「n ▸ n」）。LB 不够时游戏会消耗剩余全部；弹出「恢复LIVE BOOST」（道具/星钻/广告）时只点取消，该局改为 0（开了 `game.lb_refill` 时先用道具里的 LIVE BOOST饮料补充，见[上文](#lb-不足时用道具补充)）。留空（null）则不改游戏里的设置 |

换电脑、换模拟器实例或重装后，先用低难度打一两首，看日志里有没有同步失败或流速警告。不同电脑的截图、触控延迟不一样，不用手动调：自动修正会逐局调整时间偏移，每局最多 1ms（见[时间偏移与自动修正](#时间偏移与自动修正)）。

## 时间偏移与自动修正

`play.offset_ms` 是全局时间偏移，正值表示整体更晚按下，用来补偿截图、输入、渲染带来的延迟。本机 MuMu 实测约 -16ms 时判定居中。

每局结束后，程序读取结算页的 FAST/SLOW。FAST 多就往后推，SLOW 多就往前拉，把学到的偏移存进 `data/state.json`（与配置里的 `offset_ms` 叠加）。以下情况只记录、不修正：执行不稳定（迟到的批次多），或者 GOOD/BAD/MISS 过多（多半同步到了错误的音符）。

## 拟人化（可选，默认关闭）

让结果不那么整齐。界面里在全局选项中，命令行用 `--set` 修改：

| 配置项 | 界面选项 | 作用 |
|---|---|---|
| `play.touch.great_ratio` | 随机 GREAT（1% / 3% / 5%） | 按判定总数的这个比例，挑前后没有别的音符挨着的普通点击，提前或延后 64~69ms 打成 GREAT（单局同步误差偏大时其中一部分会变成 PERFECT 或 GOOD，GOOD 不断连击）。选曲方式为 `ap` / `ap_first` 时不生效。开启后自动修正偏移时不计 GREAT 的 FAST/SLOW |
| `play.touch.jitter_ms` | 时机偏移（±8 / ±16ms） | 按下时刻随时间缓慢漂移（最多 ± 设定值），另加每个手势最多 ±3ms 的独立抖动。上限 20ms |
| `play.touch.position_jitter` | 触控位置随机 | 触控点在音符宽度内随机横移，并上下小幅挪动。不会挪进旁边点击类音符的判定区（否则按下可能被它认领），按住的长条也不会挪进同时按住的另一个长条的判定区。取值 0~1 为幅度，界面开关打开时为 1 |

例：`ournotes-auto --set play.touch.great_ratio=0.03 --set play.touch.jitter_ms=8 --set play.touch.position_jitter=1 run`

开了「随机 GREAT」时请把游戏内节奏图示速度保持在校准过的那个值（默认 5.00）。GREAT 的判定区间是 ±83ms，
故意打的 GREAT 落在偏 64~69ms 处，留给整体偏移的余量只有十几毫秒：流速不是校准时用的值，
偏移就可能超出去，延后打的 GREAT 变成 GOOD（连击还在，但结果不对）。
流速越快，首音符的跟踪时间越短（5.00 约 1.8 秒、10.00 约 0.45 秒），单局内的同步误差也越难被平均掉，
所以这个余量在 10.00 下最紧。

## 意外情况

- 演奏中连续 `play.guard_lost_s` 秒（默认 2）看不到右上角的暂停按钮（被暂停、弹窗、闪退），就立刻停止触控，本局作废，由导航重新找回画面。设为 0 关闭这项检查
- 首音符同步失败、生命值降到 0 时，暂停后点「重试」重新开始这一局，不浪费 LB
- 画面一直认不出时，每 30 秒检查一次游戏进程；游戏闪退了就经 adb 重新启动，从标题画面重新登录。连续重启最多 2 次，回到主页后重新计数
- 没见过、只有「OK」的提示弹窗（上面没有取消、确定、购买、星钻之类的字）直接点 OK 继续，日志里会记下弹窗上的文字，截图存在 `debug/nav`
- 右上角有「跳过」的全屏演出（比如角色生日演出）点跳过；之后接着放的故事打开右上角菜单点 SKIP 跳过
- 保底：认不出的画面 60 秒一点没变，或者一直在动但 150 秒都认不出（加载、下载中不算），就重启游戏重新登录，和闪退共用上面的重启次数；重启次数用完还卡住才停下
- 游戏连续运行十几个小时后会越来越卡（从 60fps 掉到 30 多），同步失败、整首对不上。连续打歌时最近 5 次同步测到的出帧率（中位数）低于 `loop.min_fps`（默认 50，0 为不检查）就在换歌前重启游戏；重启后还是这么低（电脑本身忙不过来、模拟器限了帧率）就不再因此重启
- 服务器维护（「服务器正在维护中」页面）：挂机每 10 分钟点「返回标题画面」重新登录看一次，开服后接着挂机；其他任务直接失败
- 游戏更新：登录时的「数据下载」（追加的游戏数据）自动点 OK 下载；「检测到新版本」（要去应用商店更新安装包）不会自动点，任务直接失败，挂机也会停下，需要自己更新游戏后再开始

## 工作原理（简述）

1. **导航**：截图 → OCR → 按文字与位置判断当前画面 → 点击按钮。按钮优先按文字精确定位，找不到时用固定坐标
2. **识曲**：乐队确认页 OCR 出曲名，模糊匹配谱面站与国际服的多语言曲名，得到 musicId
3. **同步**：点击开始后，等画面静止，检测第一个音符出现在它所在轨道的上方，跟踪它的前沿。音符逼近判定线满足 `y - y_h ∝ exp(t/τ)`，拟合后外推到达时刻，由此推出歌曲的零点
4. **演奏**：谱面转换成触控手势（点击、滑动、长条、追踪），经 minitouch 注入触控（备选 MuMu IPC），高精度计时器按时发送。按游戏的判定表避开相邻音符互相「认领」触点：同时横滑的邻居错开起点，会被之后的点击认领的上划 / 追踪提前按下
5. **结算**：读取判定数与 FAST/SLOW，记录结果并修正偏移
