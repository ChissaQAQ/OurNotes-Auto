# 使い方

[README](../../README.ja.md) に書ききれない詳しい説明です：各タスクの詳細、ゲーム内設定、自動補正、人間らしさ機能、トラブル時の動作、実行時ファイルと仕組み。コマンドラインでの使い方は[コマンドライン](cli.md)を参照してください。

## 動作環境

- Windows、MuMu エミュレーター 12（本プロジェクトは MuMu 6.6.x、Android 15 インスタンスでテストしています）
- エミュレーターの解像度は **1280×720**（他の 16:9 解像度も比率で換算しますが、十分にはテストしていません）、フレームレートは 60 以上（同期パラメータは 60 fps のスクリーンショットに合わせて調整しています）
- ゲーム：国際版（パッケージ名 `com.bilibili.sirius.official`。Google Play 版は `com.bilibili.sirius` で、自動で判別します）、ゲーム言語は 简体中文、繁體中文、English、한국어 のいずれか。または日本版（パッケージ名 `com.bushiroad.sirius`）。ナビゲーションは OCR で画面上の文字を認識して行うため、他のサーバーではボタンを認識できません。한국어 の場合は「ゲーム言語」を 한국어 にしてください：初回実行時に韓国語の文字認識モデル（約 10 MB）を自動でダウンロードし、以降は毎回それも追加で読み込みます（2 つのモデルで一緒に認識するため、認識が毎回少し遅くなります）。한국어 を選ばなければ、ダウンロードも読み込みもしません
- 日本版：「ゲーム言語」を「日本語（日本版）」にすると、ゲーム起動などのタスクが日本版のクライアントを操作します（認識モデルの追加ダウンロードはありません）。日本版のクライアントは Google Play からインストールする必要があり、APK を直接インストールしたものは起動できません。アカウント切替は国際版でのみ使えます。T.G.W CARD とショップは、先にゲーム内で一度ご自身で年齢確認をしてください。未確認の間、デイリー受け取りは T.G.W CARD を飛ばします。日本版で検証済みなのはフリーライブ、AP埋め、デイリー受け取りのみで、チャレンジライブはまだ試していません
- ゲーム内設定は[ゲーム内設定](#ゲーム内設定)を参照
- 譜面サイト `assets.bdon.moe` と曲名 API `haneoka.org` にアクセスできること（アップデート確認では別途 `github.com` にアクセスします。オフにできます）
- リリースパッケージ：どちらの UI にも [VC++ 2015–2022 ランタイム](https://aka.ms/vs/17/release/vc_redist.x64.exe)（MaaFramework が依存）が必要です。MFAA には別途 .NET 10 デスクトップランタイム（同梱の `DependencySetup_依赖库安装_win.bat` で VC++ ランタイムと一緒にワンクリックでインストール可能）、MXU には WebView2（Windows 10/11 には通常プリインストール済み）が必要です。パッケージには Python ランタイム、MaaFramework、OCR モデルが同梱されており、譜面は実行時に譜面サイトからダウンロードします。各コンポーネントのライセンスは [THIRD_PARTY_NOTICES.md](../../THIRD_PARTY_NOTICES.md) を参照してください
- ソースから実行する場合：Python ≥ 3.11。[コマンドライン](cli.md)を参照

## エミュレーターへの接続

接続設定で「MuMu エミュレーター」を選び、使うエミュレーターのインスタンスを選びます。MuMu 12 の n 番目のインスタンスの adb アドレスは `127.0.0.1:16384+32n` で、たとえば 0 番目は 16384、1 番目は 16416 です。スクリーンショットとタッチは MuMu のインターフェースを通して行い、インストール先は adb のパスから割り出すため、現時点では MuMu 12 のみに対応しています。

## タスク

ゲームはホーム画面かフリーライブの選曲画面で止めておけば大丈夫です。「記録の集計」以外のタスクは、ゲームを開いていなくても先に起動し（すでに開いていればそのまま使い）、タイトル画面・ログインボーナス・お知らせを処理してゲームに入ります。

| タスク | 内容 |
|---|---|
| ゲーム起動 | ゲームが起動していなければ起動し、タイトル画面・ログインボーナス・お知らせを閉じてホーム画面に入ります。他のタスクより前に置いてください |
| アカウント切替 | 国際版のみ。現在の bilibili アカウントからログアウトし、ゲームのログイン履歴から入力したアカウントを選んでログインして（パスワード不要）、ホーム画面に入ります。すでにゲーム内にいるときは、先にゲームを再起動してタイトル画面に戻ります。アカウント名にはログイン履歴に表示される名前を入力します。一部だけでも構いませんが、1 つのアカウントにだけ一致するようにしてください。切り替えられるのはログイン履歴にあるアカウントだけなので、新しいアカウントは先にゲームで一度手動でログインしてください。複数のアカウントを交互にプレイするには、タスク一覧を「アカウント切替（A）→ 他のタスク → アカウント切替（B）→ 他のタスク」の順に並べます。アカウントセンター（Account Center）の「アカウント削除」や、ログイン履歴の各行右側にある ⓧ は押しません。演奏記録と記録まとめは、現時点ではアカウントを区別しません |
| 繰り返しプレイ | フリーライブで連続して演奏します。選曲方法（現在の曲 / ランダム / 未AP曲優先 / 指定した曲リスト）、難易度、プレイ回数、1 回あたりの LB 消費を選べます。難易度が「高難易度優先」のとき、「未AP曲優先」は EXPERT から EASY まで順に埋め、すべて終わったら EXPERT でランダムにプレイします。その他の選曲方法では EXPERT でプレイします |
| LB消化 | LIVE BOOST がなくなるまで連続して演奏します（毎回開始前に所持数を確認し、0 なら終了）。スターは使いません。プレイヤーランクが上がると LB が全回復するので、プレイ回数が見込みより多くなることがあります |
| 放置周回 | LB消化と同じく LB がなくなるまでプレイした後、バンド確認画面（Formation）で待機し、右上の回復カウントダウンを見ながら LB が 1 回あたりの消費数まで回復するのを待って、またプレイします（LB は 30 分ごとに 1 回復するので、消費 3 なら約 90 分に 1 回）。1 回あたりの消費を 0 にすると LB を待ちません：毎回開始前に所持数を確認し、LB があれば 1 消費し、なくなったら消費 0 に切り替えてプレイを続け、回復したらまた消費して、ずっと曲をプレイします。手動で止めるかプレイ回数に達するまで動き続けます。待機中に日付変更があると再ログインし、サーバーメンテナンスに当たったら 10 分ごとに確認して、メンテナンスが明けたら放置を再開します。オプション「定期回収」（デフォルトはオン、間隔 4 時間）：開始時にまずスタジオ練習（Studio Practice）を 1 回回収し、その後は設定した時間（1〜12）ごとに、プレイの合間や LB 待ちの間にホーム画面に戻ってもう一度回収し、終わったら放置に戻ります（スタジオ練習は最大 12 時間まで貯まり、超えると効率が 30% に下がります）。回収できなかったときは 30 分後にもう一度試します。オプション「毎日デイリー受け取り」（デフォルトはオン、22:30）：毎日設定した時刻（PC のローカル時刻）に、同じようにホーム画面に戻ってミッション、ミッションパス、期間限定ミッション、ビギナーミッション、T.G.W CARD、プレゼントボックスを 1 回受け取ります。受け取りきれなかったときは 10 分後にもう一度受け取ります（1 日最大 3 回）。タスク一覧の「デイリー受け取り」は放置の前に 1 回だけ実行されるので、放置中に日をまたいだ後はこのオプションで受け取ります。ゲームは毎日 23:00 に日付が変わるため、その日の分を受け取るには受け取り時刻を 23:00 より前にする必要があります。スターは使いません。このタスクは自分では終わらないので、タスク一覧の最後に置いてください |
| AP埋め | 選んだ難易度（EXPERT / HARD / NORMAL / EASY）でまだ ALL PERFECT していない曲を AP にします。選曲画面を一時的に「すべて」カテゴリに切り替え、「ALL PERFECT未達成」（NO ALL PERFECT）で絞り込みます。正常に終了したら元に戻します |
| チャレンジライブ | 一部のイベント期間中のみ開催されます（開催していないときはエラーで終了）。ライブTOP（LIVE）から「チャレンジライブ」に入って連続して演奏し、毎回 LB ではなくチャレンジpt（CP）を消費して、CP が 1 回分に足りなくなるまでプレイします。保有数が選んだ消費量に足りないとゲームが OK を押させない（「チャレンジptが足りません。」と表示される）ため、そのときは「キャンセル」を押して停止します。OK を連打してタイムアウトすることはありません。オプション「1 回あたりのチャレンジpt消費」はデフォルトが 200（×1。最も節約でき、多く周回できます）で、400 / 800 / 1600（報酬 ×2 / ×4 / ×8）や、ゲーム内の設定を変えないことも選べます。1 回目の前に「CP設定」で選び、ラジオボタンを確認してから OK を押します。選曲方法「全曲を順番にプレイ」（デフォルト）は毎回一覧の次の曲に切り替え、最後まで行ったら最初の曲に戻ります。「未AP曲を優先」は毎回開始前に 1 曲ずつ、選んだ難易度が ALL PERFECT 済みかを確認し、未 AP の曲を先にプレイします（同じ曲は最大 3 回まで）。すべて AP 済みになったら順番にプレイします（難易度が「高難易度優先」のときは EXPERT → HARD → NORMAL → EASY の順に埋めます）。現在選択中の曲をプレイし続けることもできます。バンド確認画面の「スキップ」は押しません |
| デイリー受け取り | スタジオ練習（回収）、ミッション、パスミッションと PASS の通常枠（パスが複数あるときは 1 つずつ受け取り）、期間限定ミッション、ビギナーミッション、T.G.W CARD、プレゼントボックスの報酬を順に受け取ります。項目ごとにオフにできます。押すのは点灯している「一括受け取り」（Claim All）と報酬ポップアップの OK だけです。T.G.W CARD ではデイリーポイント、デイリー報酬、ショップのカタログショップ（Catalog Shop）で価格が「無料」の商品を受け取り、スターが必要なものは押しません。認識できないポップアップは押さず、エラーで停止します。デイリーミッションは曲をプレイしないと達成されないので、演奏タスクの後に置きます。オプション「ストーリー閲覧（スキップ）」（デフォルトはオフ）：未読のバンドストーリー、アナザーストーリー、絆ストーリー（Bond Story）を 1 話ずつスキップして読み終え、楽曲を解放し、読み終えた報酬を受け取ります。各話の初回はデータのダウンロードが必要です（ボイスなし、バンドストーリーで約 30MB）。オプション「イベントストーリー（スキップ）」（デフォルトはオフ）：期間限定イベント中、ライブTOP →「イベント」からイベントページに入り、「イベントストーリー」にある未読のイベントストーリー、アナザーストーリーを 1 話ずつスキップして読み終えます。期間限定イベントがないときはこの項目をスキップします |
| 記録まとめ | このツールの演奏記録をログに出力します。エミュレーターは操作しません |

### LB不足時にアイテムで補充

繰り返しプレイ、LB消化、放置周回、AP埋めにはオプション「LB不足時にアイテムで補充」（デフォルトはオフ）があります：毎回開始前に LB の所持数が 1 回あたりの消費数より少ないとき、「LB消費」→「回復」から入り、「アイテム」タブでのみブーストドリンク（Boost Drink）を使ってその回の分を補充します（先に小型の +1 を使い、足りなければ +10 を使います）。選んだ個数、回復のプレビュー、確認ポップアップの数字がすべて一致したときだけ OK を押します。「アイテム」タブでない場合や、一つでも一致しないところがある場合はキャンセルを押し、今回の実行ではそれ以上補充しません。スターは絶対に使わず、広告も見ません。

サブオプション「補充上限」は今回の実行で補充する LB の上限で、0 ならドリンクがなくなるまで補充します。ドリンクがなくなったら元の方法で続けます（LB消化はそこで終了し、放置周回は回復待ちを始めます）。1 回あたりの LB 消費を 1〜3 に設定する必要があります。

### その他のオプション

- デフォルト以外のパラメータ（タイミングオフセットなど）を調整したいときは、[config.example.yaml](../../config.example.yaml) を展開先フォルダの `config.yaml` にコピーして編集してください。UI のオプションのほうが優先されます。
- 画面のログはデフォルトでは進捗と結果だけを表示します。全タスク共通のオプション「デバッグログ」をオンにすると、同期、譜面、タッチなどの詳細も表示されます。完全なログは常に `data/ournotes.log` に書き込まれます。
- 全タスク共通のオプション「アップデート確認」はデフォルトでオンです：タスクが終わるたびに、GitHub に新しいリリースがあればログでダウンロード先をお知らせします。自動ダウンロードはしないので、更新するには新しい圧縮ファイルを手動でダウンロードしてください。

## ゲーム内設定

| 設定 | 推奨 | 説明 |
|---|---|---|
| ノーツスピード | **5.00**（必須） | 同期パラメータ `play.sync.tau_s = 0.835` は 5.00 で測定したものです。毎回開始前にライブ前設定（Pre-LIVE Option Settings）のポップアップからスピードを読み取って確認しますが、一致しなくてもログで警告するだけで止まりません：他のスピードでも同期はできますが、押すタイミング全体がずれます。5.00 に戻すか、`calibrate motion` を実行して測り直してください（[人間らしさ](#人間らしさ任意デフォルトはオフ)の節にあるスピードの注意点も参照） |
| MV / 背景 | オフ、または暗めで動かない背景に変更（必須） | 開始時は画面が静止するのを待ってから最初のノーツを追跡します。背景が動き続けていると最大 4 秒待ったところで追跡を始め、明るい背景も混ざってしまうため、同期の失敗やずれの原因になります |
| 小節線表示（詳細 → ノーツ表示設定） | オン・オフどちらでも可 | 開始時に最初のノーツを追跡するとき、レーンを横切る小節線を認識して無視します。0.1.3 以前のバージョンは最初のノーツより先に落ちてくる小節線を最初のノーツと誤認し、その回全体が早くなってすぐにライフが 0 になるので、これらのバージョンを使う場合はオフにしてください |
| エフェクト・演出レベル | 必須ではないが、PC の性能が低い場合は下げることを推奨 | 画面を見るのは開始直後の数秒だけで（このときはまだタップエフェクトがありません）、カラフルなエフェクトは除外します。その後は譜面どおりに演奏し、右上のポーズボタンだけを見ます。ただし現時点では下げた設定でしかテストしておらず、高エフェクトでは明るい白の開幕エフェクトが追跡領域に混ざったり、全画面演出がポーズボタンを 2 秒以上隠し続けて演奏画面から離れたとみなされ、タッチが止まったりする可能性があります。下げるとエミュレーターのフレームレートも安定します |
| バンド確認画面の「LB消費」 | 設定項目 `game.lb_cost`（0〜3）で自動設定 | 1 回目の前に自動でポップアップを開いて選び、確認します。ゲームはこの設定を記憶します。0 なら LB を消費しません（LIVE START に「n ▸ n」と表示されます）。LB が足りないときはゲームが残りをすべて消費します。「LIVE BOOST回復」（アイテム / スター / 広告）が表示されたらキャンセルだけを押し、その回は 0 にします（`game.lb_refill` をオンにしているときは、先にアイテムのブーストドリンクで補充します。[上記](#lb不足時にアイテムで補充)を参照）。空欄（null）ならゲーム内の設定を変更しません |

PC やエミュレーターのインスタンスを変えたり、再インストールしたりした後は、まず低難易度で 1〜2 曲プレイし、ログに同期失敗やスピードの警告がないか確認してください。PC ごとにスクリーンショットやタッチの遅延は異なりますが、手動で調整する必要はありません：自動補正が 1 回ごとにタイミングオフセットを最大 1ms ずつ調整します（[タイミングオフセットと自動補正](#タイミングオフセットと自動補正)を参照）。

## タイミングオフセットと自動補正

`play.offset_ms` は全体のタイミングオフセットで、正の値は全体的に遅く押すことを意味し、スクリーンショット・入力・描画による遅延を補うためのものです。MuMu での実測では、約 -16ms で判定が中央に来ました。

毎回終了後、プログラムはリザルト画面の FAST/SLOW を読み取ります。FAST が多ければ遅らせ、SLOW が多ければ早めて、学習したオフセットを `data/state.json` に保存します（設定の `offset_ms` に加算されます）。次の場合は記録するだけで補正しません：実行が不安定なとき（遅れたバッチが多い）、または GOOD/BAD/MISS が多すぎるとき（たいていは間違ったノーツに同期しています）。

### 譜面ごとの補正

ずっと FAST 寄り、あるいは SLOW 寄りになる譜面があります（4 回以上プレイした 56 譜面のうち 22 譜面は平均のずれが大きめでした）。そのような譜面にグローバルなオフセットが引っ張られます。`play.auto_tune.per_chart`（デフォルトでオン）を有効にすると、ある譜面の直近 `chart_plays` 回（デフォルト 3）の偏りがグローバルの直近の傾向と逆向きで、平均の絶対値が `chart_threshold`（デフォルト 0.4）以上だった場合、そのずれはその譜面自身のものとして扱い、その譜面のオフセットだけを調整します（1 譜面あたり ±`chart_max_ms`、デフォルト ±10ms まで）。その回はグローバルオフセットを動かしません。譜面のオフセットはノーツスピードごとに別々に記録されるので、スピードを変えたら学び直しになります。

`ournotes-auto records` で確認すると、学習済みの譜面オフセットも（ずれの大きい順に）表示されます。`ournotes-auto records --clear-chart-offsets` ですべての譜面オフセットを消去でき（グローバルな学習値はそのまま）、ゲームの更新などで譜面が大きく変わったあとに一度消して学び直すとよいです。

## 人間らしさ（任意、デフォルトはオフ）

結果が整いすぎないようにします。UI では全タスク共通のオプションにあり、コマンドラインでは `--set` で変更します：

| 設定項目 | UI のオプション | 内容 |
|---|---|---|
| `play.touch.great_ratio` | ランダム GREAT（1% / 3% / 5%） | 判定総数に対してこの割合で、前後に他のノーツが近くにない通常のタップを選び、64〜69ms 早く／遅く押して GREAT にします（その回の同期誤差が大きいと、一部は PERFECT や GOOD になります。GOOD でもコンボは途切れません）。選曲方法が `ap` / `ap_first` のときは無効です。オンにすると、オフセットの自動補正では GREAT の FAST/SLOW を数えません |
| `play.touch.jitter_ms` | タイミングのゆらぎ（±8 / ±16ms） | 押す時刻が時間とともにゆっくりずれていき（最大 ± 設定値）、さらにジェスチャーごとに最大 ±3ms の独立したぶれが加わります。上限は 20ms |
| `play.touch.position_jitter` | タッチ位置ランダム | タッチ位置をノーツの幅の範囲でランダムに横へずらし、上下にも少し動かします。隣のタップ系ノーツの判定エリアには入りません（入ると押下がそのノーツに取られることがあります）。押さえているロングノーツも、同時に押さえている別のロングノーツの判定エリアには入りません。0〜1 の値が幅で、UI のスイッチをオンにすると 1 になります |

例：`ournotes-auto --set play.touch.great_ratio=0.03 --set play.touch.jitter_ms=8 --set play.touch.position_jitter=1 run`

「ランダム GREAT」をオンにしているときは、ゲーム内のノーツスピードをキャリブレーションした値（デフォルト 5.00）のままにしてください。GREAT の判定幅は ±83ms で、
わざと出す GREAT は 64〜69ms ずれた位置で押すため、全体のずれに使える余裕は十数ミリ秒しかありません。スピードがキャリブレーション時の値と違うと、
ずれが余裕を超えて、遅らせて押した GREAT が GOOD になることがあります（コンボは続きますが、結果は狙いどおりになりません）。
スピードが速いほど最初のノーツを追跡できる時間が短く（5.00 で約 1.8 秒、10.00 で約 0.45 秒）、1 回の中での同期誤差も平均化されにくくなるため、
この余裕は 10.00 で最も小さくなります。

## トラブル時の動作

- 演奏中に右上のポーズボタンが `play.guard_lost_s` 秒（デフォルト 2）続けて見えないと（一時停止、ポップアップ、クラッシュ）、すぐにタッチを止めてその回を無効にし、ナビゲーションで画面を取り戻します。0 にするとこのチェックをオフにします
- 最初のノーツの同期に失敗したときやライフが 0 になったときは、一時停止して「リトライ」を押し、その回をやり直します。LB は無駄になりません
- 画面がずっと認識できないときは 30 秒ごとにゲームのプロセスを確認し、ゲームがクラッシュしていれば adb で再起動して、タイトル画面から再ログインします。連続での再起動は最大 2 回までで、ホームに戻るとカウントがリセットされます
- 見たことのない、「OK」だけの通知ポップアップ（キャンセル、決定、購入、スターといった文字がないもの）はそのまま OK を押して続行し、ポップアップの文字をログに残して、スクリーンショットを `debug/nav` に保存します
- 右上に「スキップ」がある全画面演出（キャラクターの誕生日演出など）はスキップを押します。その後に続けて流れるストーリーは、右上のメニューを開いて SKIP を押してスキップします
- 最終手段：認識できない画面が 60 秒まったく変化しない、または動き続けているのに 150 秒認識できない（読み込み中・ダウンロード中は除く）ときは、ゲームを再起動して再ログインします。クラッシュ時と同じ再起動回数を共有し、回数を使い切ってもまだ止まっているときに停止します
- ゲームを十数時間続けて動かしていると次第に重くなり（60fps から 30 台に落ちる）、同期失敗や曲全体のずれが起きます。連続プレイ中、直近 5 回の同期で測ったフレームレート（中央値）が `loop.min_fps`（デフォルト 50、0 でチェックしない）を下回ると、曲を変える前にゲームを再起動します。再起動後も同じように低い（PC 自体の処理が追いつかない、エミュレーターがフレームレートを制限している）場合は、それを理由にした再起動はもう行いません
- サーバーメンテナンス（「サーバーメンテナンス中」の画面）：放置周回は 10 分ごとに「タイトルへ戻る」を押して再ログインし、メンテナンスが明けたら放置を再開します。他のタスクはそのまま失敗します
- ゲームの更新：ログイン時の「データダウンロード」（追加のゲームデータ）は自動で OK を押してダウンロードします。「新しいバージョンを検出」（ストアでアプリ本体を更新する必要があるもの）は自動では押さず、タスクはそのまま失敗し、放置周回も止まります。自分でゲームを更新してから再開してください

## 仕組み（概要）

1. **ナビゲーション**：スクリーンショット → OCR → 文字と位置から現在の画面を判断 → ボタンをタップ。ボタンはまず文字から正確に位置を特定し、見つからないときは固定座標を使います
2. **曲の識別**：バンド確認画面で曲名を OCR で読み取り、譜面サイトと国際版の多言語の曲名とあいまい一致させて musicId を得ます
3. **同期**：開始を押した後、画面が静止するのを待ち、最初のノーツがそのレーンの上方に現れたことを検出して、その先端を追跡します。ノーツが判定ラインに近づく動きは `y - y_h ∝ exp(t/τ)` に従うので、フィッティングして到達時刻を外挿し、そこから曲のゼロ点を求めます
4. **演奏**：譜面をタッチジェスチャー（タップ、フリック、ロング、トレース）に変換し、minitouch でタッチを注入（予備として MuMu IPC）、高精度タイマーで時間どおりに送ります。ゲームの判定表に従って、隣り合うノーツがタッチを互いに「取り合う」のを避けます：同時に横フリックする隣のノーツは開始点をずらし、後のタップに取られてしまう上フリック / トレースは早めに押します
5. **リザルト**：判定数と FAST/SLOW を読み取り、結果を記録してオフセットを補正します
